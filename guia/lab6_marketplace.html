1

Obtener el listing de clima (UI o SQL)

~2 min
UI
En este paso: Obtenemos gratis datos de clima del Marketplace, compartidos en vivo por el proveedor, sin copiar archivos ni crear pipelines.
Criterio de exito: La base ZTS_WEATHERSOURCE aparece en el explorador de objetos y el rol PUBLIC puede leerla.

Tasty Bytes sospecha que el clima mueve sus ventas, pero no tiene datos meteorologicos propios. En el Snowflake Marketplace un proveedor comparte su base en vivo (Secure Data Sharing): no hay archivos, ni ETL, ni copias; solo una base de solo lectura que apunta a los datos del proveedor. Elige uno de los dos caminos.

Camino A - UI (Snowsight):

  1. En el menu izquierdo ve a Data Products > Marketplace.
  2. En el buscador escribe Weather Source frostbyte.
  3. Abre el listing "Pelmorex Weather Source: Frostbyte" y pulsa Get.
  4. En Options nombra la base ZTS_WEATHERSOURCE, dale acceso al rol PUBLIC y confirma con Get.

Camino B - SQL: el mismo resultado con una sentencia. CREATE DATABASE ... FROM LISTING equivale al boton Get (si ya lo hiciste por UI, el IF NOT EXISTS no hace nada). IMPORTED PRIVILEGES es el permiso unico que da lectura sobre toda una base compartida.

SQLInstalar listing por SQL
-- Solo accountadmin puede instalar listings
USE ROLE accountadmin;

-- Instalar el listing gratuito por SQL (equivale al boton "Get")
CREATE DATABASE IF NOT EXISTS zts_weathersource FROM LISTING 'GZSOZ1LLEL';

-- Da acceso a la base compartida a todos los roles
GRANT IMPORTED PRIVILEGES ON DATABASE zts_weathersource TO ROLE public;
Que deberias ver

Database ZTS_WEATHERSOURCE successfully created. (o already exists si usaste la UI) y Statement executed successfully. Listing verificado: "Pelmorex Weather Source: Frostbyte" (global name GZSOZ1LLEL).

2

Explorar el dato del proveedor y cruzarlo con tus ciudades

~1 min
SQL
En este paso: Exploramos el clima del proveedor y lo filtramos a las ciudades donde opera Tasty Bytes con una vista.
Criterio de exito: El SELECT devuelve 10 filas de clima y harmonized.daily_weather_v se crea sin error.

Cambiamos al rol analista y miramos el dato tal como lo publica el proveedor: clima diario por codigo postal (temperatura, lluvia, viento...). Lo consultas como cualquier tabla propia.

SQLContexto y vista previa
-- Contexto: rol analista, base y warehouse
USE ROLE tb_analyst;

USE DATABASE tb_101;

USE WAREHOUSE tb_analyst_wh;

-- Datos de clima diario por codigo postal, compartidos en vivo por el proveedor
SELECT * FROM zts_weathersource.onpoint_id.history_day LIMIT 10;
Que deberias ver

10 filas con columnas como postal_code, country, date_valid_std, avg_temperature_air_2m_f y tot_precipitation_in.

Ahora creamos una vista que se queda solo con el clima de las ciudades donde opera Tasty Bytes: une la tabla de clima con los codigos postales del proveedor y con nuestra tabla raw_pos.country. Es SQL estandar sobre una base compartida.

SQLVista de clima diario
-- Vista: clima diario en las ciudades donde opera Tasty Bytes
CREATE OR REPLACE VIEW harmonized.daily_weather_v
COMMENT = 'Clima diario (Weather Source) en las ciudades de Tasty Bytes'
AS
SELECT
    hd.*,
    TO_VARCHAR(hd.date_valid_std, 'YYYY-MM') AS yyyy_mm,
    pc.city_name AS city,
    c.country    AS country_desc
FROM zts_weathersource.onpoint_id.history_day hd
JOIN zts_weathersource.onpoint_id.postal_codes pc
  ON pc.postal_code = hd.postal_code AND pc.country = hd.country
JOIN raw_pos.country c
  ON c.iso_country = hd.country AND c.city = hd.city_name;
Que deberias ver

View DAILY_WEATHER_V successfully created.

3

Unir ventas (1st party) con clima (3rd party)

~1 min
SQL
En este paso: Unimos nuestras ventas con el clima de terceros en una vista lista para analizar el impacto del tiempo en el negocio.
Criterio de exito: La vista analytics.daily_sales_by_weather_v se crea sin error.

La segunda vista resume las ventas diarias por ciudad desde analytics.orders_v (dato propio) y les pega temperatura promedio, precipitacion y viento maximo (dato de terceros) con un LEFT JOIN por fecha, ciudad y pais.

SQLVista ventas por clima
-- Vista: ventas diarias + clima por ciudad (1st party + 3rd party)
CREATE OR REPLACE VIEW analytics.daily_sales_by_weather_v
COMMENT = 'Ventas diarias de Tasty Bytes enriquecidas con clima'
AS
WITH ventas AS (
    SELECT DATE(o.order_ts) AS fecha, o.primary_city AS ciudad, o.country AS pais,
           SUM(o.price) AS ventas_diarias
    FROM analytics.orders_v o
    GROUP BY ALL
)
SELECT
    v.fecha, v.ciudad, v.pais, v.ventas_diarias,
    ROUND(AVG(w.avg_temperature_air_2m_f), 1)     AS temp_promedio_f,
    ROUND(AVG(w.tot_precipitation_in), 2)         AS precipitacion_in,
    ROUND(AVG(w.max_wind_speed_100m_mph), 1)      AS viento_max_mph
FROM ventas v
LEFT JOIN harmonized.daily_weather_v w
  ON w.date_valid_std = v.fecha AND w.city = v.ciudad AND w.country_desc = v.pais
GROUP BY ALL;
Que deberias ver

View DAILY_SALES_BY_WEATHER_V successfully created.

Datos de terceros sin ETL

Acabas de hacer un JOIN entre tus ventas y la base de un proveedor externo sin mover un solo byte: no hubo pipeline, ni archivo, ni copia. Si el proveedor actualiza su dato, tu vista lo ve al instante.

4

Analisis: llueve = venden menos? (Seattle)

~1 min
SQL
En este paso: Probamos con datos si la lluvia reduce las ventas en Seattle y lo graficamos sin salir del SQL File.
Criterio de exito: La consulta devuelve los dias de febrero 2022 en Seattle con ventas, temperatura, precipitacion y viento, y lo graficas en Snowsight.

Seattle es famosa por la lluvia: ideal para probar la hipotesis. Consultamos febrero de 2022 dia por dia.

SQLSeattle, febrero 2022
-- Llueve = venden menos? Seattle, febrero 2022
SELECT fecha, ventas_diarias, temp_promedio_f, precipitacion_in, viento_max_mph
FROM analytics.daily_sales_by_weather_v
WHERE ciudad = 'Seattle' AND fecha BETWEEN '2022-02-01' AND '2022-02-28'
ORDER BY fecha;
Que deberias ver

Una fila por dia de febrero 2022. Primer dia verificado: 2022-02-01, ventas $234,563.25, temperatura promedio 39.4 F, precipitacion 0.03 in.

Graficalo sin salir del SQL File (UI):

  1. En el panel de resultados haz clic en Chart.
  2. Elige tipo Line, con FECHA en el eje X y VENTAS_DIARIAS como serie.
  3. Agrega PRECIPITACION_IN como segunda serie (o cambia a Bar) para comparar ventas contra lluvia.
