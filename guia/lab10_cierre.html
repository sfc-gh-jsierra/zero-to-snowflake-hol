3

Cleanup opcional

~2 min
SQL
En este paso: Borramos opcionalmente todo lo creado en el HOL para dejar la cuenta limpia y sin consumo.
Criterio de exito: Todos los bloques terminan sin errores y SHOW DATABASES LIKE 'TB_101' no devuelve filas.

Si usaste una cuenta de prueba que vas a seguir usando, libera los objetos del HOL. Si quieres seguir practicando, no lo ejecutes.

Irreversible

Estos bloques eliminan bases, warehouses, roles, el agente y las apps. No se puede deshacer, salvo con UNDROP dentro del periodo de Time Travel (los roles y warehouses no se recuperan).

Empieza, en tu SQL File, por la app Streamlit. Usamos ACCOUNTADMIN porque vamos a borrar objetos creados por varios roles.

SQLApps
-- Usa el rol administrador para limpiar
USE ROLE accountadmin;

-- Apps
DROP STREAMLIT IF EXISTS tb_101.analytics.tasty_bytes_copilot;

El agente se retira primero de Snowflake CoWork y luego se borra. El bloque EXECUTE IMMEDIATE captura la excepcion, asi no falla si el agente no estaba publicado.

SQLAgente
-- La app React se elimina desde la carpeta react-app con:  snow app teardown --force
-- Agente: quitarlo de Snowflake CoWork y borrarlo
EXECUTE IMMEDIATE $$
BEGIN
    ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT
        DROP AGENT snowflake_intelligence.agents.tasty_bytes_agent;
    RETURN 'Agente retirado de CoWork';
EXCEPTION
    WHEN OTHER THEN RETURN 'El agente no estaba publicado';
END;
$$;

-- Borra el agente
DROP AGENT IF EXISTS snowflake_intelligence.agents.tasty_bytes_agent;

Las politicas de gobierno se desasocian antes de borrar la base, y se elimina el rol del data steward.

SQLGobierno
-- Gobierno (las politicas se desasocian antes de borrar la base)
ALTER TABLE IF EXISTS tb_101.raw_customer.customer_loyalty DROP ALL ROW ACCESS POLICIES;
-- Quita las masking policies del tag PII
ALTER TAG IF EXISTS tb_101.governance.pii UNSET MASKING POLICY tb_101.governance.mask_string_pii, MASKING POLICY tb_101.governance.mask_date_pii;
-- Borra el rol de data steward
DROP ROLE IF EXISTS tb_data_steward;

Por ultimo, las bases (la del lab y la del Marketplace), los warehouses, el resource monitor y los roles.

SQLBases de datos
-- Base de datos del lab, Marketplace, warehouses y roles
DROP DATABASE IF EXISTS tb_101;
-- Borra la base del Marketplace
DROP DATABASE IF EXISTS zts_weathersource;
SQLWarehouses
-- Borra los warehouses del lab
DROP WAREHOUSE IF EXISTS my_wh;
DROP WAREHOUSE IF EXISTS tb_de_wh;
DROP WAREHOUSE IF EXISTS tb_dev_wh;
DROP WAREHOUSE IF EXISTS tb_analyst_wh;
SQLWarehouse Cortex y resource monitor
-- Borra el warehouse de Cortex
DROP WAREHOUSE IF EXISTS tb_cortex_wh;
-- Borra el monitor de recursos
DROP RESOURCE MONITOR IF EXISTS my_resource_monitor;
SQLRoles
-- Borra los roles del lab
DROP ROLE IF EXISTS tb_admin;
DROP ROLE IF EXISTS tb_data_engineer;
DROP ROLE IF EXISTS tb_dev;
DROP ROLE IF EXISTS tb_analyst;

Finalmente la app React: no vive en TB_101 sino en tu base personal USER$, asi que se elimina desde la carpeta react-app/ en tu terminal.

BASHEliminar la app React
# Elimina la app React (desde react-app)
snow app teardown --force
Que deberias ver

Cada DROP responde ... successfully dropped. (o Statement executed successfully. si el objeto ya no existia); el bloque del agente devuelve Agente retirado de CoWork o El agente no estaba publicado. Al final, SHOW DATABASES LIKE 'TB_101' no devuelve filas.
