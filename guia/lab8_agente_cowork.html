El COO de Tasty Bytes recibe decenas de reportes fragmentados: ventas en un dashboard, opiniones de clientes en otro sistema. Cruzarlos toma horas de analistas. En este lab construyes un agente de Snowflake Intelligence (CoWork) que une todo en una conversacion: entiende numeros (Cortex Analyst sobre la Semantic View del LAB 7), lee lo que dicen los clientes (Cortex Search), grafica y ademas actua con logica propia (un stored procedure de pronostico).

A diferencia del quickstart oficial, que crea el agente con clics, aqui lo creamos por SQL (infraestructura como codigo) y despues lo usamos y editamos en la UI.

Un agente no solo consulta: tambien puede actuar con logica propia. Esa logica es un SP (Stored Procedure) normal en SQL Scripting que proyecta ventas con tendencia lineal (REGR_SLOPE / REGR_INTERCEPT) sobre los ultimos 12 meses completos de ventas_diarias. Recibe la marca y los meses_futuros (acotados entre 1 y 12) y devuelve un texto. El COMMENT describe que hace: buena practica, porque el agente se apoya en descripciones.

SQLCrear sp_pronostico_ventas
-- Crea el procedimiento de pronostico lineal
CREATE OR REPLACE PROCEDURE analytics.sp_pronostico_ventas(marca STRING, meses_futuros NUMBER)
RETURNS STRING
LANGUAGE SQL
COMMENT = 'Proyecta las ventas mensuales de una marca con tendencia lineal sobre los ultimos 12 meses'
AS
$$
DECLARE
    resultado STRING;
    rs RESULTSET;
BEGIN
    rs := (
    WITH mensual AS (
        SELECT DATE_TRUNC('month', fecha) AS mes, SUM(ventas) AS ventas
        FROM tb_101.analytics.ventas_diarias
        WHERE marca ILIKE :marca
        GROUP BY mes
        QUALIFY ROW_NUMBER() OVER (ORDER BY mes DESC) BETWEEN 2 AND 13   -- 12 meses completos
    ),
    modelo AS (
        SELECT REGR_SLOPE(ventas, DATEDIFF('month', '2019-01-01', mes))     AS pendiente,
               REGR_INTERCEPT(ventas, DATEDIFF('month', '2019-01-01', mes)) AS intercepto,
               MAX(mes) AS ultimo_mes, AVG(ventas) AS promedio
        FROM mensual
    ),
    futuro AS (
        SELECT DATEADD('month', s.n, m.ultimo_mes) AS mes,
               ROUND(m.intercepto + m.pendiente * DATEDIFF('month', '2019-01-01', DATEADD('month', s.n, m.ultimo_mes)), 0) AS ventas_proyectadas
        FROM modelo m,
             (SELECT SEQ4() + 1 AS n FROM TABLE(GENERATOR(ROWCOUNT => 24))) s
        WHERE s.n <= LEAST(GREATEST(:meses_futuros, 1), 12)
    )
    SELECT 'Pronostico para ' || :marca || ' (tendencia lineal, ultimos 12 meses). '
           || 'Promedio mensual actual: $' || TO_VARCHAR((SELECT ROUND(promedio,0) FROM modelo), '999,999,999') || '. '
           || 'Proyeccion: ' || LISTAGG(TO_VARCHAR(mes, 'YYYY-MM') || ' = $' || TO_VARCHAR(ventas_proyectadas, '999,999,999'), '; ')
              WITHIN GROUP (ORDER BY mes) AS texto
    FROM futuro
    );
    LET c CURSOR FOR rs;
    OPEN c;
    FETCH c INTO resultado;
    CLOSE c;
    RETURN COALESCE(:resultado, 'No encontre ventas para la marca ' || :marca);
END;
$$;
Bug real: SELECT ... INTO con WITH en SQL Scripting

En SQL Scripting no se puede usar SELECT ... INTO cuando la consulta empieza con WITH (CTEs). La solucion del SP: asignar la consulta a un RESULTSET (rs := (WITH ...)), abrir un CURSOR sobre el y hacer FETCH c INTO resultado.

Schema AGENTS successfully created. (o un aviso de que ya existe).

CREATE AGENT ... FROM SPECIFICATION define el agente completo en YAML. PROFILE le da el nombre visible (Tasty Bytes Copilot); models.orchestration: auto deja que Snowflake elija el LLM; budget limita tiempo (120 s) y tokens por respuesta.

Las instrucciones separan dos cosas: orchestration (cuando usar cada herramienta, y usar ambas si la pregunta mezcla numeros y opiniones) y response (como contestar: espanol ejecutivo, cifra primero, bullets, grafica y recomendacion). sample_questions son las preguntas sugeridas que veras en CoWork.

Sus 4 herramientas (tools):

  • VentasTastyBytes (cortex_analyst_text_to_sql): Cortex Analyst sobre la Semantic View SV_TASTY_BYTES del LAB 7. Traduce la pregunta a SQL y la ejecuta: ventas, ordenes, ticket promedio, marcas, ciudades, productos y clima. Su descripcion aclara que NO tiene texto de reviews, para que el orquestador no la use para opiniones.
  • ReviewsClientes (cortex_search): busqueda semantica (por significado, no por palabra exacta) sobre las reviews del servicio TASTY_BYTES_REVIEW_SEARCH, filtrable por MARCA, CIUDAD y SENTIMIENTO. Devuelve hasta 5 reviews que el agente cita como fuente.
  • PronosticoVentas (generic, custom tool): llama al SP del paso 1. El input_schema declara los parametros marca y meses_futuros con su descripcion: asi el LLM sabe que valores extraer de la pregunta para invocar el procedimiento.
  • data_to_chart: genera graficas a partir de los datos devueltos por las otras herramientas (rankings, series de tiempo).

tool_resources conecta cada herramienta con su objeto real (semantic view, search service con sus columnas id/titulo, procedure) y con el warehouse TB_ANALYST_WH y su timeout.

Copia el bloque completo

Copia el bloque $$ ... $$ completo: la indentacion del YAML importa.

SQLCREATE AGENT
-- Crea el agente desde su especificacion YAML
CREATE OR REPLACE AGENT snowflake_intelligence.agents.tasty_bytes_agent
  COMMENT = 'Analista de negocio de Tasty Bytes: ventas, clientes, clima y pronosticos'
  PROFILE = '{"display_name": "Tasty Bytes Copilot", "color": "blue"}'
  FROM SPECIFICATION
$$
models:
  orchestration: auto

orchestration:
  budget:
    seconds: 120
    tokens: 32000

instructions:
  response: >
    Responde siempre en espanol, de forma ejecutiva y concisa. Empieza con la
    respuesta directa (una cifra o conclusion), luego 2-4 bullets de contexto.
    Formatea montos en USD con separador de miles. Cuando haya series de tiempo
    o rankings, genera una grafica. Cierra con una recomendacion accionable.
  orchestration: >
    Usa VentasTastyBytes para cualquier pregunta de ventas, ordenes, ticket
    promedio, marcas, ciudades, paises, productos o clima.
    Usa ReviewsClientes para saber que dicen u opinan los clientes, quejas o
    elogios; filtra por marca cuando el usuario la mencione.
    Usa PronosticoVentas solo cuando pidan proyectar, pronosticar o estimar
    ventas futuras de una marca.
    Si la pregunta combina numeros y opiniones, usa ambas herramientas y
    relaciona los hallazgos.
  sample_questions:
    - question: "Cuales son las 5 marcas con mas ventas en 2022? Muestralo en una grafica"
    - question: "Que dicen los clientes de Freezing Point?"
    - question: "Que ciudad tiene el mejor ticket promedio y que opinan ahi los clientes?"
    - question: "Pronostica las ventas de Kitakata Ramen Bar para los proximos 3 meses"
    - question: "Llueve menos = vendemos mas? Analiza Seattle en 2022"

tools:
  - tool_spec:
      type: "cortex_analyst_text_to_sql"
      name: "VentasTastyBytes"
      description: >
        Datos estructurados de Tasty Bytes (2019-2022): ventas en USD, ordenes,
        unidades, ticket promedio por marca, tipo de menu, item, ciudad, pais,
        fecha, y clima diario por ciudad. NO contiene texto de reviews.
  - tool_spec:
      type: "cortex_search"
      name: "ReviewsClientes"
      description: >
        Busqueda semantica sobre reviews escritas por clientes de los food
        trucks. Atributos filtrables: MARCA, CIUDAD, SENTIMIENTO (positive,
        negative, neutral, mixed). Usar para opiniones, quejas y elogios.
  - tool_spec:
      type: "generic"
      name: "PronosticoVentas"
      description: >
        Proyecta las ventas mensuales futuras de UNA marca usando la tendencia
        lineal de los ultimos 12 meses. Devuelve un texto con el promedio actual
        y la proyeccion mes a mes.
      input_schema:
        type: "object"
        properties:
          marca:
            type: "string"
            description: "Nombre exacto de la marca, ej. 'Freezing Point', 'Kitakata Ramen Bar'"
          meses_futuros:
            type: "number"
            description: "Cantidad de meses a proyectar, entre 1 y 12. Por defecto 3"
        required: ["marca", "meses_futuros"]
  - tool_spec:
      type: "data_to_chart"
      name: "data_to_chart"
      description: "Genera visualizaciones a partir de los datos devueltos por otras herramientas"

tool_resources:
  VentasTastyBytes:
    semantic_view: "TB_101.ANALYTICS.SV_TASTY_BYTES"
    execution_environment:
      type: "warehouse"
      warehouse: "TB_ANALYST_WH"
      query_timeout: 120
  ReviewsClientes:
    search_service: "TB_101.ANALYTICS.TASTY_BYTES_REVIEW_SEARCH"
    max_results: 5
    id_column: "REVIEW_ID"
    title_column: "MARCA"
  PronosticoVentas:
    type: "procedure"
    identifier: "TB_101.ANALYTICS.SP_PRONOSTICO_VENTAS"
    execution_environment:
      type: "warehouse"
      warehouse: "TB_ANALYST_WH"
      query_timeout: 60
$$;

Permisos y publicar en Snowflake CoWork

~1 min
SQL
En este paso: Damos permisos al analista y publicamos el agente en Snowflake CoWork para que el negocio lo use.
Criterio de exito: los GRANT se ejecutan sin error y el bloque de publicacion devuelve "Agente publicado en Snowflake CoWork" (o "El agente ya estaba publicado en CoWork").

Con RBAC (Role-Based Access Control) decides quien usa el agente: el rol tb_analyst recibe uso sobre la base, el esquema, el agente, el SP y el warehouse.

SQLPermisos
-- Da al analista acceso al agente y sus recursos
GRANT USAGE ON DATABASE snowflake_intelligence TO ROLE tb_analyst;
GRANT USAGE ON SCHEMA snowflake_intelligence.agents TO ROLE tb_analyst;
GRANT USAGE ON AGENT snowflake_intelligence.agents.tasty_bytes_agent TO ROLE tb_analyst;
GRANT USAGE ON PROCEDURE tb_101.analytics.sp_pronostico_ventas(STRING, NUMBER) TO ROLE tb_analyst;
GRANT USAGE ON WAREHOUSE tb_analyst_wh TO ROLE tb_analyst;

Ahora publicamos el agente: se agrega al objeto de Snowflake CoWork de la cuenta (en SQL conserva su nombre real SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT). Primero lo creamos si no existe y luego le agregamos el agente.

SQLPublicar en CoWork
-- Crea el objeto de CoWork si no existe
CREATE SNOWFLAKE INTELLIGENCE IF NOT EXISTS SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT;

-- (si ya estaba publicado, el bloque lo indica en vez de fallar)
EXECUTE IMMEDIATE $$
BEGIN
    ALTER SNOWFLAKE INTELLIGENCE SNOWFLAKE_INTELLIGENCE_OBJECT_DEFAULT
        ADD AGENT snowflake_intelligence.agents.tasty_bytes_agent;
    RETURN 'Agente publicado en Snowflake CoWork';
EXCEPTION
    WHEN OTHER THEN RETURN 'El agente ya estaba publicado en CoWork';
END;
$$;
Bloque idempotente

La publicacion va dentro de EXECUTE IMMEDIATE con un EXCEPTION: si el agente ya estaba publicado, devuelve un mensaje en vez de fallar. Puedes re-ejecutar este paso sin romper nada.

Probar el agente por SQL

~1 min
SQL
En este paso: Probamos el agente con una llamada SQL para confirmar que responde antes de abrirlo al negocio.
Criterio de exito: la columna RESPUESTA_AGENTE devuelve el contenido de la respuesta con las 3 marcas con mas ventas en 2022.

SNOWFLAKE.CORTEX.DATA_AGENT_RUN invoca al agente desde SQL con un mensaje en formato JSON: es la misma API que usara la app del LAB 9. TRY_PARSE_JSON(...):content extrae el contenido: texto de la respuesta, herramientas usadas y SQL ejecutado.

SQLDATA_AGENT_RUN
-- Pregunta al agente por SQL y extrae la respuesta
SELECT TRY_PARSE_JSON(
  SNOWFLAKE.CORTEX.DATA_AGENT_RUN(
    'SNOWFLAKE_INTELLIGENCE.AGENTS.TASTY_BYTES_AGENT',
    $${"messages":[{"role":"user","content":[{"type":"text","text":"Cuales son las 3 marcas con mas ventas en 2022?"}]}]}$$
  )
):content AS respuesta_agente;

Nosotros lo creamos por SQL

En el quickstart oficial el agente se crea con clics (AI & ML > Agents > Create agent) y se le agregan Cortex Analyst y Cortex Search en la pestana Tools. Nosotros hicimos lo mismo con CREATE AGENT ... FROM SPECIFICATION: es el mismo objeto, y puedes verlo y editarlo en la UI. La imagen siguiente es solo referencia; no crees otro agente.

El comportamiento del agente vive en sus instrucciones: cambiarlas no requiere codigo.

  1. AI & ML > Agents > TASTY_BYTES_AGENT > Edit.
  2. Ve a la seccion Orchestration y cambia la instruccion de respuesta (por ejemplo: "responde como un chef").
  3. Pulsa Save.
  4. Vuelve a Snowflake CoWork y repite una de las preguntas: compara el tono con la respuesta anterior.
Re-ejecutar el CREATE pisa tus cambios

Si vuelves a correr el CREATE OR REPLACE AGENT del paso 2, las ediciones hechas en la UI se reemplazan por la especificacion SQL.
