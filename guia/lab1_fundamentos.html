LAB 1: Fundamentos de Snowflake

Objetivo: entender los pilares de Snowflake: computo elastico, cache, clonacion sin copia, Time Travel y control de costos.

Vision General

Lo que vas a construir

  • Un warehouse propio que escala de XSmall a XLarge en segundos
  • Un clon de desarrollo de la tabla de camiones
  • Una correccion de calidad promovida a produccion con SWAP
  • Una tabla recuperada con UNDROP
  • Un Resource Monitor con cuota mensual

Tecnologias utilizadas

Virtual Warehouses Result Cache Zero Copy Cloning VARIANT SWAP Time Travel Resource Monitors

Por que importa

Tasty Bytes procesa cientos de millones de ordenes. Separar computo de almacenamiento le permite pagar por segundo solo lo que usa, probar cambios sobre clones gratuitos y recuperarse de errores sin restaurar backups.

1

Contexto y tu primer warehouse

~1 min
SQL
En este paso: Fijamos el contexto de trabajo y creamos nuestro primer warehouse para ver como se configura el computo en Snowflake.
Criterio de exito: my_wh aparece en el listado, suspendido.

Todo comando en Snowflake corre con un rol (que permisos tienes), una base de datos (donde estan los datos) y un warehouse (el computo que ejecuta el query). Primero fijamos el contexto y listamos los warehouses que creo el setup.

SQLContexto
-- Cambia al rol de trabajo
USE ROLE accountadmin;
USE DATABASE tb_101;

-- Lista los warehouses de la cuenta
SHOW WAREHOUSES;

Un Virtual Warehouse es computo puro, separado del almacenamiento: lo enciendes, lo apagas o lo cambias de tamano sin mover datos. Creamos el nuestro suspendido y sin auto resume, a proposito, para ver que pasa cuando no hay computo encendido.

SQLCrear my_wh
-- Creamos nuestro propio warehouse (suspendido y SIN auto resume a proposito)
CREATE OR REPLACE WAREHOUSE my_wh
    COMMENT = 'Mi warehouse de Tasty Bytes'
    WAREHOUSE_TYPE = 'standard'
    WAREHOUSE_SIZE = 'xsmall'
    MIN_CLUSTER_COUNT = 1
    MAX_CLUSTER_COUNT = 2
    SCALING_POLICY = 'standard'
    AUTO_SUSPEND = 60
    INITIALLY_SUSPENDED = TRUE
    AUTO_RESUME = FALSE;
Que significa cada parametro

WAREHOUSE_SIZE: tamano (XS a 6XL; cada talla duplica computo y costo por segundo). MIN/MAX_CLUSTER_COUNT: multi-cluster para concurrencia. AUTO_SUSPEND = 60: se apaga solo tras 60 s sin uso. AUTO_RESUME: se enciende solo al llegar un query.

Que deberias ver

Warehouse MY_WH successfully created. En SHOW WAREHOUSES veras MY_WH con estado SUSPENDED junto a TB_DE_WH, TB_DEV_WH y TB_ANALYST_WH.

2

Sin computo no hay query: RESUME y AUTO_RESUME

~1 min
SQL
En este paso: Encendemos computo propio y comprobamos que en Snowflake el almacenamiento y el computo son independientes.
Criterio de exito: El primer SELECT falla y, tras el RESUME, devuelve los camiones.

Activamos my_wh en la sesion e intentamos consultar la tabla de camiones. Como esta suspendido y sin auto resume, el query debe fallar.

SQLError esperado
-- Selecciona el warehouse de computo
USE WAREHOUSE my_wh;

-- Este query falla: el warehouse esta suspendido  (error esperado)
SELECT * FROM raw_pos.truck_details;
Error esperado

No active warehouse selected o Warehouse 'MY_WH' is suspended. Es didactico: el almacenamiento esta ahi, pero no hay computo encendido para leerlo.

Lo encendemos y activamos AUTO_RESUME para que a partir de ahora se encienda solo cuando llegue un query. Repetimos el SELECT.

SQLEncender y reintentar
-- Lo encendemos y activamos auto resume
ALTER WAREHOUSE my_wh RESUME;
ALTER WAREHOUSE my_wh SET AUTO_RESUME = TRUE;

-- Este query falla: el warehouse esta suspendido  (error esperado)
SELECT * FROM raw_pos.truck_details;
Que deberias ver

450 filas, una por food truck, con columnas como truck_id, primary_city y truck_build (un JSON).

3

Escalar en segundos y el Result Cache

~1 min
SQL
En este paso: Escalamos el warehouse en segundos y vemos como el Result Cache devuelve resultados repetidos sin gastar computo.
Criterio de exito: La segunda ejecucion del mismo query responde en milisegundos.

Vamos a sumar ventas sobre ~670 millones de lineas. Subimos a XLarge con un solo comando: no hay que mover datos ni reiniciar nada.

SQLEscalar a XLarge
-- Escala el warehouse a XLarge
ALTER WAREHOUSE my_wh SET WAREHOUSE_SIZE = 'XLarge';

Ejecuta el query y anota el tiempo que muestra Snowsight debajo de los resultados.

SQLVentas por marca
-- Ventas por marca sobre ~670 millones de lineas de detalle (anota el tiempo)
SELECT
    o.truck_brand_name,
    COUNT(DISTINCT o.order_id) AS ordenes,
    SUM(o.price)               AS ventas_totales
FROM analytics.orders_v o
GROUP BY o.truck_brand_name
ORDER BY ventas_totales DESC;

Ahora ejecuta exactamente el mismo query otra vez. Snowflake guarda el resultado 24 h en el Result Cache: si los datos no cambiaron, lo devuelve sin usar el warehouse (costo cero).

SQLMismo query, otra vez
-- Ventas por marca sobre ~670 millones de lineas de detalle (anota el tiempo)
SELECT
    o.truck_brand_name,
    COUNT(DISTINCT o.order_id) AS ordenes,
    SUM(o.price)               AS ventas_totales
FROM analytics.orders_v o
GROUP BY o.truck_brand_name
ORDER BY ventas_totales DESC;

Terminamos el calculo pesado: bajamos a XSmall. Pagas por segundo solo lo que usaste.

SQLVolver a XSmall
-- Volvemos a XSmall: pagas por segundo solo lo que usas
ALTER WAREHOUSE my_wh SET WAREHOUSE_SIZE = 'XSmall';
Que deberias ver

15 marcas ordenadas por ventas. La 1a ejecucion tarda unos segundos; la 2a, milisegundos. En el Query Profile (clic en el ID del query) la 2a muestra QUERY RESULT REUSE.

4

Zero Copy Cloning y datos semi-estructurados

~1 min
SQL
En este paso: Clonamos una tabla sin duplicar datos y consultamos campos JSON para enriquecer el catalogo de camiones.
Criterio de exito: truck_dev creado con columnas year, make y model pobladas.

La columna truck_build es un OBJECT (JSON) con anio, marca y modelo. Snowflake lo guarda nativo en VARIANT: no hay que definir esquema antes de cargar.

SQLVer el JSON
-- Consulta los datos
SELECT truck_build FROM raw_pos.truck_details LIMIT 10;

Queremos aplanar ese JSON sin tocar produccion. Creamos un clon de desarrollo: es instantaneo y no duplica almacenamiento, porque comparte los micro-particiones con el original hasta que alguno cambie.

SQLClonar y agregar columnas
-- Clon de desarrollo instantaneo, sin duplicar almacenamiento
CREATE OR REPLACE TABLE raw_pos.truck_dev CLONE raw_pos.truck_details;

-- Agrega una columna a la tabla
ALTER TABLE raw_pos.truck_dev ADD COLUMN IF NOT EXISTS year  NUMBER;
ALTER TABLE raw_pos.truck_dev ADD COLUMN IF NOT EXISTS make  VARCHAR(255);
ALTER TABLE raw_pos.truck_dev ADD COLUMN IF NOT EXISTS model VARCHAR(255);

Con la notacion columna:campo::TIPO leemos el JSON y lo convertimos en columnas tipadas.

SQLAplanar el JSON
-- Notacion ":" para leer el JSON
UPDATE raw_pos.truck_dev
SET year  = truck_build:year::NUMBER,
    make  = truck_build:make::VARCHAR,
    model = truck_build:model::VARCHAR;
Que deberias ver

number of rows updated: 450.

5

Calidad de datos y SWAP atomico a produccion

~1 min
SQL
En este paso: Corregimos datos en el clon y lo promovemos a produccion con un SWAP atomico, sin afectar a los usuarios.
Criterio de exito: En truck_details solo existe Ford (sin Ford_).

Contamos camiones por marca. Mira bien: hay un problema de calidad.

SQLDetectar el problema
-- Problema de calidad: 'Ford' y 'Ford_'
SELECT make, COUNT(*) AS camiones
FROM raw_pos.truck_dev
GROUP BY make
ORDER BY make;
Que deberias ver

Aparecen Ford y Ford_ como si fueran marcas distintas.

Lo corregimos en el clon y luego intercambiamos dev y produccion con SWAP: es un cambio de metadatos atomico, los usuarios nunca ven un estado intermedio.

SQLCorregir y promover
-- Corrige los valores mal escritos
UPDATE raw_pos.truck_dev SET make = 'Ford' WHERE make = 'Ford_';

-- Promovemos dev a produccion de forma atomica
ALTER TABLE raw_pos.truck_details SWAP WITH raw_pos.truck_dev;

Verificamos produccion y quitamos la columna JSON que ya no necesitamos.

SQLVerificar produccion
-- Cuenta registros por categoria
SELECT make, COUNT(*) AS camiones
FROM raw_pos.truck_details
GROUP BY make
ORDER BY camiones DESC;

-- Elimina la columna JSON ya extraida
ALTER TABLE raw_pos.truck_details DROP COLUMN truck_build;
Que deberias ver

Una sola fila Ford con el total combinado, y el mensaje Statement executed successfully del DROP COLUMN.

6

Time Travel: recuperar una tabla borrada

~1 min
SQL
En este paso: Borramos una tabla por error y la recuperamos con Time Travel, sin backups ni restauraciones manuales.
Criterio de exito: truck_details vuelve a existir tras el UNDROP.

Simulamos el peor dia: alguien borra la tabla de produccion. Ejecuta el DROP y luego intenta describirla.

SQLUps...
-- Borra la tabla
DROP TABLE raw_pos.truck_details;

-- No existe  (error esperado)
DESCRIBE TABLE raw_pos.truck_details;
Error esperado

Table 'TRUCK_DETAILS' does not exist or not authorized.

Con Time Travel no llamamos al DBA ni restauramos backups: UNDROP la trae de vuelta con todos sus datos. Luego borramos el clon que ya no usamos.

SQLUNDROP
-- Sin llamar al DBA ni restaurar backups
UNDROP TABLE raw_pos.truck_details;

-- Revisa los datos resultantes
SELECT * FROM raw_pos.truck_details LIMIT 10;

-- Borra la tabla
DROP TABLE raw_pos.truck_dev;

Bonus: Time Travel tambien consulta el estado de una tabla en el pasado.

SQLLa tabla hace 1 minuto
-- Bonus: Time Travel por tiempo (estado de la tabla hace 1 minuto)
SELECT COUNT(*) FROM raw_pos.truck AT(OFFSET => -60);
Que deberias ver

Table TRUCK_DETAILS successfully restored., 10 camiones y un conteo de 450.

7

Control de costos: Resource Monitor

~1 min
SQL
En este paso: Ponemos un tope de creditos al warehouse con un Resource Monitor para controlar el gasto.
Criterio de exito: MY_RESOURCE_MONITOR creado y asignado a my_wh.

Un Resource Monitor pone un techo de creditos: avisa al 75%, suspende al 90% (dejando terminar lo que corre) y corta todo al 100%.

SQLCrear y asignar
-- Crea el Resource Monitor con tope de creditos
CREATE OR REPLACE RESOURCE MONITOR my_resource_monitor
    WITH CREDIT_QUOTA = 100
    FREQUENCY = MONTHLY
    START_TIMESTAMP = IMMEDIATELY
    TRIGGERS ON 75 PERCENT DO NOTIFY
             ON 90 PERCENT DO SUSPEND
             ON 100 PERCENT DO SUSPEND_IMMEDIATE;

-- Asocia el Resource Monitor al warehouse
ALTER WAREHOUSE my_wh SET RESOURCE_MONITOR = my_resource_monitor;

-- Verifica el Resource Monitor creado
SHOW RESOURCE MONITORS LIKE 'MY_RESOURCE_MONITOR';
Que deberias ver

Una fila con credit_quota = 100, frequency = MONTHLY y used_credits cercano a 0.
