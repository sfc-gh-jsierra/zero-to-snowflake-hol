2

Audio: transcribir llamadas con SQL

~2 min
IA
En este paso: Convertimos llamadas de servicio en texto, medimos su sentimiento y obtenemos recomendaciones de mejora, todo con una consulta SQL.
Criterio de exito: Ves la transcripcion de problema-servicio.mp3 con SPEAKER_00/SPEAKER_01 y una fila por cada .mp3 con texto, sentimiento y recomendacion.

AI_TRANSCRIBE convierte audio en texto. TO_FILE apunta a un archivo del stage y la opcion timestamp_granularity: 'speaker' separa lo que dice cada hablante: ideal para una llamada de call center.

SQLUna llamada
-- Transcribe una llamada separando a cada hablante
SELECT AI_TRANSCRIBE(TO_FILE('@archivos', 'problema-servicio.mp3'),
                     {'timestamp_granularity': 'speaker'}) AS transcripcion;
Que deberias ver

Un JSON con ~71.8 s de audio y segmentos etiquetados SPEAKER_00 / SPEAKER_01.

Ahora encadenamos funciones en un solo query: un CTE transcribe todos los .mp3, AI_SENTIMENT mide el sentimiento por aspecto (profesionalismo, resolucion, tiempo de espera) y AI_COMPLETE pide a un LLM recomendaciones para el agente.

SQLTodas las llamadas
-- Todas las llamadas: transcribir, medir y recomendar en un solo query
WITH audios AS (
    SELECT relative_path,
           AI_TRANSCRIBE(TO_FILE('@archivos', relative_path)):text::STRING AS texto
    FROM DIRECTORY(@archivos)
    WHERE relative_path ILIKE '%.mp3'
)
SELECT
    relative_path,
    texto,
    AI_SENTIMENT(texto, ['profesionalismo', 'resolucion', 'tiempo de espera']) AS sentimiento,
    AI_COMPLETE('claude-sonnet-4-5',
        'Como podria mejorar el agente esta atencion? Maximo 3 bullets de 10 palabras: ' || texto) AS recomendacion
FROM audios;
Que deberias ver

2 filas (una por .mp3) con TEXTO, SENTIMIENTO (JSON por aspecto) y RECOMENDACION (3 bullets).

Momento wow: transcribir audio con SQL

Una llamada de servicio pasa de archivo .mp3 a texto, sentimiento y recomendaciones para el agente en una sola consulta, sin pipelines de voz ni servicios externos.

3

Documentos: extraer datos de contratos .docx

~2 min
IA
En este paso: Extraemos automaticamente las partes, fechas y valores de contratos Word, sin leerlos a mano ni sacar los archivos de Snowflake.
Criterio de exito: Una fila por contrato con arrendatario, arrendador, fecha_inicio, valor_contrato, inmueble_direccion y terminacion_anticipada.

AI_EXTRACT lee un documento (aqui contratos de arrendamiento en Word) y responde preguntas en lenguaje natural. En responseFormat defines cada campo como [nombre, pregunta] y obtienes un JSON con esas llaves.

SQLAI_EXTRACT
-- Extrae datos clave de cada contrato Word
SELECT
    relative_path,
    AI_EXTRACT(
        file => TO_FILE('@archivos', relative_path),
        responseFormat => [
            ['arrendatario',          'Quien es el arrendatario?'],
            ['arrendador',            'Quien es el arrendador?'],
            ['fecha_inicio',          'Fecha de inicio del contrato (YYYY-MM-DD)?'],
            ['valor_contrato',        'Valor del contrato en numeros?'],
            ['inmueble_direccion',    'Direccion del inmueble?'],
            ['terminacion_anticipada','Tiene clausula de terminacion anticipada (SI/NO)?']
        ]
    ):response AS datos_contrato
FROM DIRECTORY(@archivos)
WHERE relative_path ILIKE '%.docx';
Que deberias ver

2 filas. Contrato 01: arrendador MARIA ELENA RODRIGUEZ CASTILLO, arrendatario CARLOS ANDRES MORENO LOPEZ.

Momento wow: contratos a datos

De un .docx sin estructura a columnas consultables, listas para cruzar con tablas del negocio.

4

Imagenes: cedula, seguridad industrial y peritaje

~2 min
IA
En este paso: Usamos IA de vision para leer una cedula, revisar seguridad industrial en una foto y peritar un choque para seguros.
Criterio de exito: Obtienes el JSON de la cedula, una inspeccion de TELCO.png y un peritaje de choque.png.

Los LLM multimodales leen imagenes. Con PROMPT('... {0}', TO_FILE(...)) insertas la imagen en el lugar {0} del prompt. Primero, verificacion de identidad: una foto de una cedula a JSON.

SQLCedula a JSON
-- Lee la cedula y devuelve sus datos en JSON
SELECT AI_COMPLETE('claude-sonnet-4-5',
    PROMPT('Extrae de esta cedula en JSON: numero, nombres, apellidos, fecha_nacimiento, lugar_nacimiento, es_mayor_de_edad (SI/NO). Solo el JSON. {0}',
           TO_FILE('@archivos', 'cedula.jpg'))) AS cedula;
Que deberias ver

Un JSON con nombres GERONIMO, apellidos VELEZ RUIZ, fecha y lugar de nacimiento y mayoria de edad.

Puedes elegir el modelo. Para seguridad industrial usamos pixtral-large (Mistral) y para el peritaje de seguros volvemos a claude-sonnet-4-5.

SQLInspeccion y peritaje
-- Seguridad industrial en una foto de campo (otro modelo: pixtral-large de Mistral)
SELECT AI_COMPLETE('pixtral-large',
    PROMPT('Describe la imagen en espanol con: cantidad_personas, usan_elementos_seguridad, tipo_elementos, zona_senalizada, tipo_trabajo (suelo/altura), riesgos. {0}',
           TO_FILE('@archivos', 'TELCO.png'))) AS inspeccion;

-- Peritaje de un choque para seguros
SELECT AI_COMPLETE('claude-sonnet-4-5',
    PROMPT('Eres perito de seguros. Describe danos visibles, severidad (baja/media/alta) y partes a reparar. {0}',
           TO_FILE('@archivos', 'choque.png'))) AS peritaje;
Que deberias ver

TELCO.png: 2 personas trabajando en una torre con casco y arnes. choque.png: Renault Twingo vs motocicleta, con danos, severidad y partes a reparar.

Bug real: TELCO.png devolvia NULL

En la validacion, TELCO.png devolvia NULL con claude-sonnet-4-5. Con pixtral-large (Mistral) describe correctamente la escena. Leccion: si un modelo no responde con una imagen, prueba otro modelo multimodal.
